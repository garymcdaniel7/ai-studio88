## Objective

Wire speed/motion-quality verbs into the H3 prompt builder's `integrated_multimodal_description` field so every generated prompt includes explicit motion-quality language in the action clause. The rule exists in the `h3-video-production` skill and in @ai-studio's brain doc but has never been codified in code.

## Where it lives

The injection target is the `integrated_multimodal_description` section of the H3 5-part prompt format (used by `build_sunstone_api.py`, `build_obsidian_h3_official_api.py`, and the Ref2VA prompt builders).

The subject → action → camera → style flow places speed verbs between the subject and the camera description:

```
<subject> + <speed verbs> + <action> + <camera> + <environment>
```

## Speed verb payload

Vocabulary validated by Gary (from `h3-video-production` skill):

| Intensity | Verbs |
|-----------|-------|
| High | `whip-fast acceleration`, `fast powerful motion`, `bursting speed` |
| Medium | `rapid`, `quick`, `fast-flowing`, `smooth momentum` |
| Low | `steady`, `easy`, `soft glide`, `slow drift` |
| Negative space | `still`, `motionless`, `locked`, `held position` |

Also inject the **framing-guarantee sentence** variant where applicable to prevent temporal drift:

> "The framing is the same in every frame of the take: [specific positional details locked in place throughout]."

## Acceptance criteria

1. Every prompt generated by the builder scripts contains speed verbs in the action clause of `integrated_multimodal_description` — never a bare action without motion quality.
2. Speed-verb strength is configurable per shot (high/medium/low/negative) so a director can dial motion intensity across segments.
3. Existing prompts without speed verbs are NOT broken — the injection only adds, never replaces.
4. A dry-run flag (`--dry-run`) prints the final prompt without submitting to the queue, so Gary can review the injection before rendering.
5. `--speed` flag or per-shot parameter in the JSON builder.

## Implementation sketch

- **Builder scripts:** `build_sunstone_api.py` and `build_obsidian_h3_official_api.py` under `~/.hermes/productions/`
- **Add function:** `inject_speed_verbs(prompt: str, intensity: str = "medium") -> str` that parses the `integrated_multimodal_description:` block and inserts the speed verbs after the subject clause
- **Flag:** `--speed <high|medium|low|negative>` in the builder entry points (default: `medium`)
- **Per-shot override:** Allow `--speed-shot <shot_index>:<value>` for multi-shot chains

## Verification

1. `python3 build_sunstone_api.py --seed 42 --prompt "..." --speed high --dry-run` → output prompt contains motion-quality language in action clause
2. `python3 build_sunstone_api.py --seed 42 --prompt "..." --speed negative --dry-run` → output contains `still`/`held position` language
3. Existing `--help` and flags remain functional
4. No regression on actual renders in the queue
